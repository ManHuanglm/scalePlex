# 多品牌条码标签秤管理软件｜详细开发任务清单

软件定位：跨平台（Compose Multiplatform）、多语言、替代TOP2000，支持PLU管理、标签模板、下发、日志读取、多秤集群管理；驱动抽象架构，方便新增品牌。

> 
> 目标适配清单（前面规划）：一期：寺冈DIGI、大华、友声、辉宏；二期：托利多、CAS、顶尖；三期：石田、碧彩等
> 架构分层：**UI层 ↔ 业务服务层 ↔ 驱动抽象层 ↔ 通信层（TCP/UDP/Serial）**
> 技术栈默认：Kotlin + Compose Multiplatform（Windows/macOS/Linux桌面端），数据库：SQLite；配置文件：JSON；日志：SLF4J

## 一、前期准备（预研任务，0阶段）

1. 寺冈DIGI SM系列 UDP协议（TOP2000同款）
   - 抓包：PLU上传/下载、标签模板、时间同步、读取交易记录、秤状态查询
   - 整理字段：PLU号、品名、单价、条码、包装号、税率、预包装、快捷键、标签格式ID
2. 大华 TM系列 TCP协议（4001端口）
3. 辉宏 HL系列 UDP协议
4. 友声 条码秤 TCP/串口协议
5. 托利多 8442/3880 TCP协议（区分新旧版本）
6. CAS CL-5200 UDP协议

- 输出物：每个品牌一份协议文档、报文样例、异常报文（超时、校验失败）
- 风险点记录：部分秤协议无官方文档，依赖抓包；不同固件版本协议存在差异

### 任务2：基础技术方案确定

1. 驱动抽象接口定义（IScaleDriver）【重点，后面直接给代码】
2. 通信模块封装：TCP客户端、UDP客户端、RS232串口（rxtx / jserialcomm）
3. 数据库表结构设计（PLU、标签模板、秤设备、分组、交易日志、用户、配置）
4. 多语言方案：i18n 资源文件（zh-CN / en-US，预留其他语言）
5. 项目结构、模块拆分

   - `core`：公共模型、工具、i18n、常量

   - `driver-impl`：各品牌驱动实现（digi、dahua、hihong、yousheng...）
   - `communication`：tcp/udp/serial通信
   - `db`：sqlite数据库访问层
6. 打包方案：Windows exe、mac dmg、Linux deb；版本号、自动更新预留

3. 定义UI术语中英对照（后续给翻译）

## 二、核心底层模块开发（阶段1，优先做，支撑寺冈驱动跑通）

> 
> 目标：底层稳定，先跑通【寺冈SM系列】对标TOP2000基础下发

### 2.1 通信模块 communication

1. TCP Client 封装
   - 连接、断开、重连机制、超时设置、心跳
   - 发送报文、接收报文、分包处理、自动重连策略
2. UDP Client 封装（无连接，应答等待、重试）
   - 发送请求，等待应答，超时重试、丢包处理
3. Serial串口封装（RS232）
   - 波特率、数据位、校验位、停止位配置
4. 统一通信异常回调：连接失败、超时、校验错误、断连事件
5. 通信日志：原始报文记录（调试开关，正式版可关闭）

### 2.2 驱动抽象层 driver-api

1. 定义 `IScaleDriver` 接口，统一方法

```
// 方法清单
suspend fun connect(): Result<Unit>
suspend fun disconnect()
suspend fun getStatus(): ScaleStatus // 在线/离线、秤型号、固件版本
suspend fun downloadPlu(plu: PluItem): Result<Unit> // 单条PLU下发
suspend fun downloadPluBatch(list: List<PluItem>): Result<BatchResult> //批量下发
suspend fun deletePlu(pluNo: String): Result<Unit>
suspend fun deleteAllPlu(): Result<Unit>
suspend fun uploadPlu(): Result<List<PluItem>> //从秤读取PLU
suspend fun syncTime(): Result<Unit>
suspend fun downloadLabelTemplate(template: LabelTemplate): Result<Unit>
suspend fun readTradeLog(): Result<List<TradeRecord>> //读取交易流水
suspend fun clearTradeLog(): Result<Unit>
```

2. 定义公共数据模型：
   - ScaleDevice：秤信息（品牌、型号、ip、端口、串口参数、驱动类型、分组）
   - PluItem：PLU主体（pluNo, name, nameEn, price, barcode, tax, unit, hotKey, etc.）
   - LabelTemplate：标签模板（模板ID、尺寸、元素列表）
   - TradeRecord：交易记录（时间、PLU、重量、金额）
   - BatchResult：批量下发结果（成功条数、失败列表、错误信息）
3. 驱动工厂 `ScaleDriverFactory`：根据设备品牌自动实例化对应驱动

### 2.3 数据库模块 db

表清单：

1. `scale_device` 秤设备表
2. `scale_group` 秤分组表（总部批量下发到一组秤）
3. `plu` PLU商品表（支持多语言名称、多条码、税率、预包装标识）
4. `label_template` 标签模板表
5. `trade_log_local` 本地缓存交易流水（从秤读取后存入）
6. `app_config` 软件配置（语言、通信超时、默认品牌、自动更新）
7. `operation_log` 操作日志（谁什么时候下发PLU，哪个秤，成功失败）

- 功能：CRUD、分页查询、条件筛选、数据库备份/恢复
- 迁移脚本：版本升级自动迁移表结构

### 2.4 业务服务层 service

1. ScaleService：设备管理、驱动实例缓存、批量分组下发
2. PluService：PLU增删改查、导入导出（Excel / CSV）、批量修改
3. LabelService：标签模板管理
4. TradeLogService：流水查询、导出Excel
5. ConfigService：全局配置、语言切换

## 四、UI桌面端开发（Compose Multiplatform，阶段3，可以和驱动并行开发）

### 4.1 主框架 & 布局

1. 主窗口：菜单、工具栏、左侧设备树（分组+秤）、中间PLU列表、底部状态栏
2. 设备树：在线/离线图标，右键菜单：连接、断开、同步时间、读取PLU、读取流水
3. 全局多语言切换：设置里切换中文/英文，界面实时刷新，无需重启
4. 主题：浅色/深色模式

### 4.2 设备管理页面

1. 添加秤：选择品牌型号、IP、端口、串口参数、归属分组
2. 编辑、删除、批量导入秤（Excel）
3. 设备状态实时轮询：后台心跳检测，在线状态自动刷新
4. 分组管理：新建分组，把多个秤加入分组，支持**分组一键下发PLU**（核心卖点）

### 4.3 PLU管理模块（核心）

1. PLU列表展示、筛选、搜索（PLU号、品名、条码）
2. PLU编辑弹窗：
   - 商品编号、名称（中文+英文）、单价、单位、税率、条码、快捷键
   - 支持预包装、固定重量标识
3. 新增、复制、删除PLU
4. 批量导入（Excel/CSV模板导出）、批量导出PLU
5. 批量修改：统一改税率、统一加价、统一归属标签模板
6. 下发操作：下发到单台秤 / 下发到整个分组
7. 从秤上读取PLU，回写到本地库（秤→软件反向同步）

### 4.4 标签模板编辑器（重点难点）

> 
> 对标TOP2000标签编辑，支持可视化拖拽

1. 新建标签：选择标签尺寸（40*30、58*40等）
2. 拖拽元素：文本（中英）、条码、二维码、重量、单价、金额、日期、LOGO
3. 元素属性：字体、字号、位置、对齐、旋转
4. 模板保存、另存为、导出导入模板
5. 模板下发到秤
6. 预览：渲染标签效果图

### 4.5 交易流水模块

1. 读取秤交易记录，存入本地数据库
2. 流水查询：时间范围、PLU筛选、按秤筛选
3. 流水导出Excel
4. 清空秤内流水

### 4.6 系统设置界面

1. 语言切换 zh-CN / en-US
2. 通信参数：超时时间、重试次数、心跳间隔
3. 数据库备份、自动备份路径
4. 日志级别、报文调试开关
5. 软件版本、关于页面

### 4.7 弹窗与辅助UI

- 批量下发进度弹窗：进度条、成功/失败列表
- 错误提示、告警、操作成功toast
- 报文调试窗口（开发调试用，可隐藏给普通用户）
